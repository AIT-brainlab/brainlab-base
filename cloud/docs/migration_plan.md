## 2. Service 1: NetBird Migration (Self-Hosted On-Prem $\rightarrow$ NetBird Cloud)

### Objective
Migrate all lab devices and compute nodes from the local self-hosted NetBird server to **NetBird Managed Cloud** (`app.netbird.io`), eliminating local server maintenance and enabling 1-click Google Login for `@ait.asia` and `@gmail.com` members.

### Step-by-Step Migration Execution

1. **Step 1: Create NetBird Cloud Management Account**
   - Log into [`app.netbird.io`](https://app.netbird.io) using `brainlab@ait.asia`.
   - Enable Google OAuth2 Single Sign-On.
   - Generate a primary **Setup Key** for lab infrastructure servers.

2. **Step 2: Invite Lab Members**
   - In NetBird Cloud dashboard $\rightarrow$ `Users` $\rightarrow$ invite members by entering their `@ait.asia` and `@gmail.com` emails.

3. **Step 3: Migrate On-Premise Nodes & NAS (`cairo`)**
   - SSH into each local machine and run:
     ```bash
     # Disconnect from old on-premise NetBird server
     netbird down
     
     # Connect to NetBird Managed Cloud
     netbird up --management-url https://api.netbird.io --key <NEW_CLOUD_SETUP_KEY>
     ```
   - Verify connection in NetBird Cloud dashboard (`Peers` tab).

4. **Step 4: Decommission Local NetBird Server**
   - Once all nodes report `Connected` status on NetBird Cloud, stop and remove local NetBird containers:
     ```bash
     docker stop netbird-management netbird-signal
     docker rm netbird-management netbird-signal
     ```

## 3. Service 2: DNS Migration (Local On-Prem DNS $\rightarrow$ GCP Cloud DNS)

### Objective
Migrate domain resolution for `brain.cs.ait.ac.th` and `dpi.ait.ac.th` from the local DNS server to **GCP Cloud DNS** in `ait-brainlab-mgmt` for 100% SLA uptime.

### Step-by-Step Migration Execution

1. **Step 1: Export On-Premise DNS Zone Records**
   - Export all active DNS records (A, AAAA, CNAME, TXT, MX, SRV) from the local DNS server configuration file.

2. **Step 2: Replicate Records in GCP Cloud DNS**
   - In GCP Console $\rightarrow$ `ait-brainlab-mgmt` $\rightarrow$ `Network services` $\rightarrow$ `Cloud DNS`.
   - Replicate records into:
     - Managed Zone 1: `brain.cs.ait.ac.th`
     - Managed Zone 2: `dpi.ait.ac.th`

3. **Step 3: Parent NS Record Delegation**
   - Copy the 4 NS records generated by GCP Cloud DNS (e.g. `ns-cloud-a1.googledomains.com`).
   - Submit NS record updates to parent domain admin (`cs.ait.ac.th`).

4. **Step 4: Dual Resolution Verification**
   - Test resolution against Google Public DNS and GCP Cloud DNS:
     ```bash
     dig @8.8.8.8 brain.cs.ait.ac.th +short
     dig @ns-cloud-a1.googledomains.com brain.cs.ait.ac.th +short
     ```

5. **Step 5: Decommission Local DNS Server**
   - Once DNS TTL expires (24-48 hours) and public traffic resolves via GCP Cloud DNS, shut down the local DNS server.

## 4. Service 3: LDAP Migration (On-Prem LDAP $\rightarrow$ Cloud `lldap`)

### Objective
Migrate user directory authentication from on-premise LDAP to **`lldap`** (Serverless Cloud Run or lightweight compute), preserving existing Unix UIDs and GIDs so NFS home directory permissions on NAS (`cairo:/mnt/HDD/home`) remain 100% intact.

### Step-by-Step Migration Execution

1. **Step 1: Export On-Premise User Directory & UIDs**
   - Dump user accounts and UIDs/GIDs from on-premise LDAP:
     ```bash
     ldapsearch -x -b "dc=brain,dc=cs,dc=ait,dc=ac,dc=th" "(objectClass=posixAccount)" uid uidNumber gidNumber mail
     ```

2. **Step 2: Deploy `lldap` Cloud Instance**
   - Deploy `lldap` container to GCP Cloud Run (or `ait-brainlab-mgmt` VM).
   - Set Base DN: `dc=brain,dc=cs,dc=ait,dc=ac,dc=th`.

3. **Step 3: User Import & UID/GID Alignment**
   - Create user entries in `lldap` matching exported UIDs/GIDs and emails (`@ait.asia` / `@gmail.com`).
   - *Critical*: Ensure Unix UID for `akraradet` in `lldap` matches the owner of `/mnt/HDD/home/akraradet` on NAS `cairo`.

4. **Step 4: Update SSSD Configuration on Compute Nodes & NAS**
   - On local Ubuntu machines and NAS `cairo`, update `/etc/sssd/sssd.conf`:
     ```ini
     [domain/default]
     id_provider = ldap
     auth_provider = ldap
     ldap_uri = ldap://<LLDAP_CLOUD_IP_OR_NETBIRD_IP>:389
     ldap_search_base = dc=brain,dc=cs,dc=ait,dc=ac,dc=th
     ldap_id_use_start_tls = false
     ```
   - Restart SSSD: `sudo systemctl restart sssd`

5. **Step 5: Verify Unix User & NAS Permissions**
   - Test user lookup: `getent passwd <username>`
   - Verify NFS NAS mount permissions: `ls -la /mnt/HDD/home/<username>`
   - Test SSH login with test user.

6. **Step 6: Decommission Local LDAP Server**
   - Once all nodes successfully authenticate against `lldap`, stop local LDAP service:
     ```bash
     sudo systemctl stop slapd
     sudo systemctl disable slapd
     ```
